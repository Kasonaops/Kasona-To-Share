# Tools: the catalog and the picker

A lens supplies a worldview. A tool supplies a method. This page is the picker: which tool for
which question shape. Three rules apply to every tool.

1. **Name the tool out loud when you use it.** "I am running a pre-mortem, not a debate" tells you
   what kind of answer is coming. A tool applied silently is indistinguishable from an opinion.
2. **The shape transfers, the content does not.** Buckets, kill reasons and horizons are rewritten
   per domain (see the domain packs). Copying another domain's version verbatim is the most
   likely way to misuse a tool.
3. **One tool per question, usually.** Tools stack badly. A pre-mortem inside a MECE structure
   inside a four-round debate produces a document, not a decision.

## The picker

| Question shape | Tool | Lives in |
| --- | --- | --- |
| Any decision with no single obviously correct answer | OOC/EMR as the container | `../../decision-partner/references/decision-frameworks.md` section 6 |
| "Is this even the next thing to do?" | Next, Best, Affordable | `next-best-affordable.md` |
| "Should we stop or shrink X" where X already exists and runs | Kill review | `kill-review.md` |
| "Should we commit to X" (a build, launch, price change, hire, move) | Pre-mortem with Tiger, Paper Tiger, Elephant triage. The most transferable tool: it needs only a commitment and a horizon | `../../decision-partner/SKILL.md` step 5 |
| Entering something (a client, partner, job, venture, deal) and the checks are running in parallel | Gate ladder | `gate-ladder.md` |
| Long or overlapping option set, or "did we miss one" | MECE sorting | `../../decision-partner/SKILL.md` step 2 |
| "Should we still be doing it this way" (direction, not execution) | Temporal triangulation | `../../decision-partner/SKILL.md` step 2 |
| Reversibility is the real question (a price, a public position, a hire, a move) | One-way versus two-way doors | `../../decision-partner/references/decision-frameworks.md` section 2 |
| Two sources point in different directions | Believability weighting, stated as a judgement, never a score | `../../board-of-advisors-blueprint/references/thinking-tools-integration.md` |
| Your own answer to "what do I want" is vague | Future-retrospective question | `sharp-questions.md` |
| A genuine strategic fork with no clearly correct answer | Four-round debate | `../../board-of-advisors-blueprint/references/session-protocol.md` |
| After the decision, so a review can learn from it | Decision quality versus outcome quality, rejected options, revisit triggers | `../../decision-partner/references/decision-journal.md` |

## Writing your own tool

Copy `_template.md`, fill the five sections, add a row to `../../PLUGGED-IN.md`. If a tool
overlaps more than half with an existing one, extend the existing one instead of adding a file.
